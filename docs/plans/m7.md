## M7.0.1: Parity follow-up against the official SDK (user, 2026-11-20)

M6.0.2 compared the fork and PdMount with the official SDK at `cs/v0.33.0` (`docs/sdk-parity.md`). Since then the
official SDK released `cs/v0.33.1` (2026-11-18) and `js/v0.24.0` (2026-11-19). The community SDK (`proton-sdk-rs2`) has
released nothing after 0.5.1 (2026-11-01; one release-script commit since, checked 2026-11-20), so the fork's base is
unchanged.

1. Update the reference checkout (`PDMOUNT_CS_SDK`) to the newest official tags (take the newest when the task runs) and
   the `cs/` row of AGENTS.md's citation table.
2. Read the **whole** diff from `cs/v0.33.0` (and `js/v0.23.0`) to the new tags, the C# and JS SDK and `cs/README.md`;
   Swift, Kotlin, CI and translation changes only where they show a protocol or service-rule change. Note that commits
   dated before `cs/v0.33.0` can be missing from that tag (it sits on a release line), so compare by ancestry, not date.
3. **Leads** (from the commit titles only, 2026-11-20; not analysed, neither complete nor conclusions):

   | Commit | Title | Area to check |
   |---|---|---|
   | `36cd76df` | fix(client)!: preserve timezone offset in modification time | XAttr modification time as written and read (P4, P5, PdMount's XAttr); what other clients now write |
   | `40b64798` | feat(client-js): verify and expose membership acceptedBy on nodes | P24 membership acceptance, D132/P27 verification |
   | `5ee47d5c` | fix(client-js): stop polling scopes removed while their events are fetched | Event polling of a share that goes away mid-poll (M6.0.8, D112) |
   | `0d9bbb98` | fix(client-js): avoid logging block tokens | P16, no secrets in logs |
   | `0f0ae7d9` | fix(client-js): report no content author error for revisions without extended attributes | P27 and D132 (unverified signatures), P4 |
   | `48f82555`, `50a4648b` | close file handles when upload stops early; yield all invitations before throwing | probably not applicable |

4. Output: a dated section in `docs/sdk-parity.md` ("Follow-up to `<new tag>`"), one row per change that touches an area
   of the report: official behaviour, fork, PdMount, status, severity, proposed action (a patch P31…, a PdMount change, or
   accepted with the reason). A finding that affects correctness, data written for other clients, or the service rules
   is High.
5. Nothing else changes in this task; fixes are picked by the user afterwards.
