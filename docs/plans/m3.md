## Context

M2 is done (TODO.md, 2026-10-22). M3 (DESIGN.md §16) adds:
- remote changes to dirty inodes and the full conflict engine (§10);
- offline mode (§9.6);
- auth refresh and `needs_login` (§12.2–§12.3);
- the use of fork patches P9, P11 and P12;

Exit criteria:
- M1–M7, and every R/G/A scenario in `second` mode on two real profiles;
- zero data loss;
- remote changes visible within the SLO;
- a 3 h soak on the fake (D048; 24 h before).

The user plans with Opus, implements with Sonnet (one task per session), and reviews with Opus at the end. This plan must therefore be self-contained: every design decision is made here, not by the implementer.

Decisions taken with the user on 2026-10-22 (recorded as D037–D039 in M3.0):
- **D037:** the visibility SLO becomes "within `sync.poll_interval` + 10 s (40 s at the default)". D033 stays.
- **D038:** a new fork patch P14 adds rename/move with a caller-supplied original name hash and exposes a decoded node's name hash. Each rename also gets a fresh pre-check.
- **M3.1:** the Q1/Q6 check is the first task, run by Opus, once the user has logged in profile `second`.
- **D039:** the plan lives in the repo at `docs/plans/m3.md`. Sonnet commits after each task once `scripts/ci.sh` passes; no push.

Today's state, from code exploration:
- **Conflicts.** The `conflicts` table and `inodes.remote_newer` exist in `store/0001.sql` but are unused. Content conflicts park in RAM (`journal.rs` "conflict handling: M3"). Rename conflicts retry with a fresh hash, so local intent always wins. Remote deletes resurrect the whole subtree (`vfs.rs` `forget_remote_subtree`).
- **Offline, auth, `needs_login`.** None of these exist yet:
  - `timeouts.offline_read` is never read;
  - no 401 retry;
  - the daemon exits when the session is rejected;
  - connection errors probably classify as `Other` (the `reqwest_middleware` wrapper hides `reqwest::Error`).
- **Tests.** Missing: a `second` verify mode, M1–M7, fake pause points, faults togglable for a running daemon, a soak script, and the property invariants "no acknowledged content unreachable" and "two cores converge".

### Ground rules for all tasks

- **Locks (DESIGN.md §4.3).**
  - A staging lock is taken before the tree lock, never while holding it.
  - No lock is held across `.await`.
  - Inode numbers are allocated (`Engine::allocate_inos`, async) before any lock is taken.
  - The new conflict-registry mutex is a leaf: never take it while holding the tree, staging or access lock. Compute paths first.
  - Kernel invalidations go only through `apply_changes` (the notify task).
- **Detection.** Conflicts are detected by comparing revisions, never by event kind. On the real API, a new revision arrives as `UpdateMetadata`, and a rename or trash as `UpdateContent` (DESIGN §9.3). The base revision is the staging sidecar's `base_rev()` (`staging.rs`), or `node.remote.rev` when there is no staging.
- **Style.** Match the surrounding code: comment density, naming, error enums, `tracing` fields, test helper reuse (`engine/tests.rs` `seeded`, `open_with`, `running`, `settle`, `write_file`, `read_file`, `remote_child`, `listed`; `fake_fs.rs` `fake_tree`, `read_all`).
- **Unsafe code is denied.** Use `nix`, not `libc`.
- **No new crate dependencies** unless the task names them.
- **The SDK fork's files mix CRLF and LF** (TODO Handoff notes). Edit them only with tools that keep line endings.

## M3.2: Error classification fixes (`crates/pdmount-backend/src/proton.rs`)

Bugs found by reading the code (none of them covered by a test yet):

1. **Connection errors.**
   - Drive API calls go through `reqwest_middleware` (0.5.2). Its `Error::Reqwest` is `#[error(transparent)]`, so `reqwest::Error` never appears in `anyhow::Error::chain()`, and `map_error` returns `Other` instead of `Offline`.
   - Add `reqwest-middleware` (same version as the SDK's lock entry) to `pdmount-backend`.
   - Write `fn transport_error(error: &anyhow::Error) -> Option<&reqwest::Error>`. It searches the chain for `reqwest::Error`, or for `reqwest_middleware::Error::Reqwest(e)`.
   - Use it in `map_error`: `is_connect()` → `Offline`, `is_timeout()` → `Transient`.
   - **Test:** a real request through a `reqwest_middleware::ClientBuilder` client to `http://127.0.0.1:1/`, wrapped in `anyhow`, maps to `Offline`. Also cover the plain `reqwest` path.
2. **401 in a 200 body.** If `ApiError` exposes the body `Code`, treat `Code == 401` as `Unauthorized` too (the SDK's `ensure_authenticated` documents this case, SDK `proton-sdk-rs2/src/session.rs:515-526`). Add a test.
3. **Block download errors.** Map `HttpTransferError` and `TooManyRequestsException` (SDK `proton-drive-sdk/src/block/download.rs`; look up the exact types):
   - 429 → `RateLimited{retry_after}`;
   - 5xx and timeouts → `Transient`;
   - connection failures → `Offline`.
   
   Add tests that construct the errors.
4. **Fix the stale citations** in DESIGN §12.3: `rs2/auth.rs:99` → `:284`, `:144` → `:335` (fork lines).

Done: tests pass; the journal no longer parks queued work after 5 connection failures (the `Offline` error is retryable, `journal.rs` `permanent_reason`).

## M3.4: Conflict naming (pure) (new `crates/pdmount-core/src/conflicts.rs`)

`lib.rs`: add `pub mod conflicts;`. Core `Cargo.toml`: `chrono.workspace = true`.

```rust
pub fn conflict_name(name: &str, device: &str, at: SystemTime, attempt: u32) -> String
fn split_extension(name: &str) -> (&str, &str)   // (stem, ext including the dot)
fn sanitize_device(device: &str) -> String       // '/', '(', ')' and control chars -> '_'; empty -> "remote"
```

- **Suffix:** `format!(" (conflict {device} {YYYY-MM-DD HH-MM-SS} UTC{n})")`, where `n` is `""` for `attempt <= 1`, else `" {attempt}"`. The time is UTC via `chrono::DateTime::<Utc>::from(at)`.
- **Extension split:**
  - split at the last `.` whose byte index is > 0, so `.bashrc` has no extension;
  - `foo.` gives the extension `"."`;
  - if `ext.len() + suffix.len() > 254`, use `ext = ""` and `stem = name`.
- **Truncation:** cut the stem to the largest char boundary with `stem.len() + suffix.len() + ext.len() <= 255`. Walk `char_indices`; `floor_char_boundary` is unstable.
- **Tests:**
  - `conflict_names_follow_the_design_example`: `report.odt`, `laptop`, at 2026-10-19 14:03:27 UTC → `report (conflict laptop 2026-10-19 14-03-27 UTC).odt`;
  - `the_extension_is_split_at_the_last_dot` (`archive.tar.gz`);
  - `leading_dot_names_keep_the_whole_name` (`.bashrc`; `.config.json` → stem `.config`);
  - `names_without_extension_and_with_a_trailing_dot`;
  - `the_collision_number_goes_inside_the_parentheses`;
  - `long_names_are_cut_at_a_char_boundary` (250 × `é`);
  - `a_huge_extension_moves_into_the_stem`;
  - `device_names_are_sanitized`;
  - `names_are_deterministic_for_a_fixed_clock`.

## M3.7: Tree resolution primitives (`vfs.rs`, pure, unit tests only)

**`Changes`** gains `pub vanished: Vec<Ino>`, `pub clashes: Vec<Ino>`, `pub notes: Vec<ConflictNote>` and `pub remote_newer: Vec<Ino>`.

New `Tree` methods, all synchronous:

**1. `split_conflict`:**
```rust
pub fn split_conflict(&mut self, ino, server: RemoteState, new_ino, now) -> Option<(Changes, ConflictNote)>
```
- Precondition: `ino` is an attached file and `node.remote.link == server.link`. Otherwise return `None`.
- Let `P` = the parent, `N` = the name, `C = pick_conflict_name(P, N, |_| false)`.
- On X:
  - `set_remote(ino, None)`, `remote_newer = false`;
  - move the child entry in `P` from `N` to `C`; `ctime = now`;
  - `P.mtime = P.ctime = now`.
- Insert the server version Y: `D = by_link(server.parent_link)`. If `D` is attached, a listed folder, and lacks `server.name`, insert `Node::from_remote(new_ino, D, server, File)`. Otherwise do not insert; the next listing will.
- Changes:
  - changed `[X, P, Y?, D?]`;
  - invalidations `Entry{P,N}`, `Entry{P,C}`, `Inode{P}`, plus `Entry{D,server.name}` and `Inode{D}` if Y was inserted (deduped).
- Note: `EditEdit{ino: X, other_ino: Y, link, orig_name: N, conflict_name: C, remote_rev: server.rev}`.

**2. `yield_name`:**
```rust
pub fn yield_name(&mut self, ino, now) -> Option<(Changes, String, String)>
```
A local rename of X within its parent to `pick_conflict_name`. No remote change.

**3. `unbind_tombstone`:**
```rust
pub fn unbind_tombstone(&mut self, ino) -> Option<Changes>
```
Requires `deleted`. Does `set_remote(None)`, `deleted = false`, `removed.push`, and `drop_node` if droppable.

**4. `adopt_remote_placement`:**
```rust
pub fn adopt_remote_placement(&mut self, ino) -> Option<Changes>
```
- Requires `D = by_link(remote.parent_link)` attached and a listed folder, `!is_within(D, ino)`, and the name free or held by `ino`.
- Moves the node there, as in the follower branch of `apply_listing_at` (≈923-937).
- Invalidations: `Entry` for the old and new names, `Inode` for both directories.

**5. `resurrect_minimal`:**
```rust
pub fn resurrect_minimal(&mut self, top) -> Resurrected { changes, kept: Vec<Ino>, removed_renamed: Vec<Ino> }
```
- Post-order over the subtree. `keep(n) = n.local_only || n.remote.is_none() || content_pending || meta_pending || (file && gens.content != gens.uploaded_content) || any child kept`.
- Kept nodes:
  - `set_remote(None)`, `remote_newer = false`;
  - a file with `Content::Remote` gets `gens.content = uploaded_content + 1` (it is staged later from the old revision, as `forget_remote_subtree` did).
- The topmost non-kept nodes:
  - remove from the parent's children;
  - `Invalidation::Delete{parent, child, name}`;
  - `remove_subtree`;
  - nodes inside them with `placement_pending` (computed before the removal) go into `removed_renamed`.
- `Inode` invalidation for each directory whose children changed.

**6. Invariants check:**

Checks:

## M3.19.2: Block pool reserved at startup (`crates/pdmount-core/src/pool.rs`, new; `cache.rs`)

All RAM-cache memory is reserved when the cache opens. Afterwards the cache never calls the allocator for block data.
The number of startup allocations does not matter; that they all happen at startup does (D049).

- **Pool:** one region per size class, mapped with `mmap(MAP_PRIVATE | MAP_ANONYMOUS | MAP_POPULATE)` through
  `nix::sys::mman::mmap_anonymous` (add the `mman` feature to the workspace `nix`; no new crate), so RSS includes the
  pool from the start. No `MADV_FREE`: the pool's memory stays resident.
  - Classes: 64 KiB, 1 MiB and 4 MiB + 40 bytes (room for the nonce and tag, so a slot can hold a sealed block).
  - The split of `ram_bytes` across classes is fixed in code, about 1/8, 1/4 and 5/8. It always gives at least 2 slots of
    the largest class; startup fails with a clear error if `ram_bytes` is too small for that.
  - A block uses the smallest class it fits in.
- **Slots:** a free list per class. A taken slot is handed out as `Bytes` through `Bytes::from_owner` (bytes 1.12), with
  an owner that returns the slot to its free list on drop.
  - The RAM cache LRU holds these `Bytes`. A reply holding a clone keeps the slot alive.
  - Eviction drops the LRU's reference. The slot is free once the last clone is gone.
- **Taking a slot when none is free:** evict LRU entries of that class until one is free.
  - Hot path (`get_local`): never wait. If every slot of the class is still referenced, fall back to a heap allocation,
    count it in a new metric `cache_pool_fallbacks`, and don't insert the block into the LRU.
  - Slow path (`seed`, downloads): wait on a per-class `tokio::sync::Notify` with a 5 s cap, then fall back the same way.
- **`seed`:** takes a slot of the class that fits each block, reads into it, encrypts in place
  (`AeadInPlace::encrypt_in_place_detached`), and writes the nonce, ciphertext and tag from the slot. No `vec![0; block_size]`
  and no `encrypt` allocation.
  - `DiskCache::put` gets the same in-place form for every caller.
  - The block does not go into the RAM LRU (unchanged; uploads don't fill RAM).
- **Accounting:** `RamCache.bytes` counts slot sizes, not block lengths, so `ram_bytes` is the real upper bound.
  `pd stats` shows the slots in use per class, plus the new fallback metric.
- **Tests:**
  - Unit tests: slot reuse, eviction with a held clone, fallback when every slot is held, and that `seed` round-trips
    through the disk cache.
  - An allocation-count test: a counting `#[global_allocator]` in a test binary. After warm-up, 1000 RAM hits and 100 disk
    hits make no allocation of 64 KiB or more.
- DESIGN.md §6.2: the pool, the classes, the fallback and the metric. §3.4: the cold-read flow says "into a pool slot".

## M3.19.3: Reads through the pool (`cache.rs`, `engine.rs`, `pdmount-fuse`, `pdmount-backend`)

- **Disk-cache hit:** `pread` the sealed file straight into a slot, then `decrypt_in_place_detached`. No `std::fs::read`,
  no `decrypt` allocation.
- **Download:** `Backend::fetch_block` gets a sibling, `fetch_block_into(&self, …, buf: &mut [u8]) -> Result<usize>`. The
  default implementation calls `fetch_block` and copies.
  - The fake implements it directly: it reads the blob into `buf`.
  - The proton adapter keeps the default: the SDK allocates its own buffers, and changing that would need a fork patch
    (out of scope; note it as an M4 option in TODO.md).
  - The verified plaintext then goes into the RAM LRU from the slot, and into the disk cache in place.
- **Reply without `assemble`:** when a read lies inside one block (the common case), the engine returns that block's
  `Bytes` sliced to the range, and fuser replies from the slice. `ReplyData::data(&[u8])` copies into the kernel; nothing
  is allocated.
  - Only a read that spans two blocks assembles. It uses a scratch buffer of 1 MiB (the largest FUSE read, `max_pages` 256),
    one per fuser thread, reserved at startup.
- **Dirty reads:** reads of dirty inodes (§6.5) are not changed; they read from staging and stay as they are.
- **Engine read API:** returns an enum `ReadData { Slice(Bytes), Owned(Vec<u8>) }` (`Owned` covers staging and the
  fallback). Update the three `assemble` callers (`engine.rs` ≈1134, ≈1826, ≈1866).
